    Matroska tags

    Matroska tags associate named values with specified targets such as tracks or the broader resource, retaining scope, language and default-value relationships.

    Matroska tags can describe particular targets within a media resource. A tag is not necessarily a global label for the entire file.

    A target establishes which entity receives the value

    Consider an original conceptual hierarchy:

    Tag
  Targets
    TrackUID: 12
  SimpleTag
    TagName: TITLE
    TagString: Director commentary

    Here, the title belongs to the targeted track. It should not automatically replace the movie's displayed title.

    The hierarchy names the relevant concepts; it is not an encoded EBML file or a complete tag-interchange XML document.

    Track identity and menu position differ

    A TrackUID identifies a track relationship in the resource. A player's “audio track 2” can be a selection ordinal in its current menu.

    Those values should not be substituted for one another. A remux can alter ordering while retaining another identity relationship, or recreate track identities while preserving the audio content.

    Value Scope
    Global title tag Applicable broader target
    Track-targeted title A particular track
    Track selection index A consumer's selection context
    Provider work identifier An external catalogue relationship

    For Emby, the source target and imported field explain whether “Director commentary” belongs in an audio-track label or the library's work title.

    Languages and defaults can coexist

    A tag can carry language/default information. Several title values can therefore be intentional alternatives rather than duplicate corruption.

    The consumer needs a selection rule and the intended scope. Flattening all values into one string loses those relationships; selecting the first encountered value can choose an unintended language.

    Language tags explains the wider language-identification concepts. The applicable Matroska field/version determines its precise representation.

    Moving containers can change tag mapping

    Another container may not provide the same target/value organization. A converter must decide what to retain and how to map it.

    Preserving the video/audio packets does not inherently preserve every descriptive target.
