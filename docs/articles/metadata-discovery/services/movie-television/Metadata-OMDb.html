    The Open Movie Database (OMDb)

    OMDb exposes title search and record retrieval with distinct query parameters, IMDb references and a separately documented poster service.

    OMDb, The Open Movie Database, offers a web API for movie and related title information. Its publisher distinguishes searching a set of candidates from retrieving a particular record.

    Query parameters express different questions

    Parameter Documented purpose
    s Search by title wording
    i Retrieve using an IMDb title identifier
    t Retrieve using title wording
    type Narrow the title category
    y Supply release-year context
    plot Select a short or full plot representation

    An integration with an uncertain title can first search candidates. A known identifier can instead support a more specific lookup.

    The result's interpretation still needs the entity context. A series and an episode have related descriptions without being interchangeable title records.

    External keys retain their namespace

    OMDb accepts IMDb title references. That relationship does not make the two services identical or make every response field originate from one universal catalogue.

    For an Emby comparison, keep the selected provider, the lookup identity and the returned record together. IMDb identifiers explains the key's form and scope.

    A localized library title or a user edit can then coexist with that identity. It need not be replaced merely to make the display wording match the search hint.

    A content label and an opinion score differ

    A response can provide descriptive ratings-related information. A parental/content classification and an audience or critic score answer different questions.

    A score of eight on a ten-point opinion scale is not an age threshold. Content ratings develops the scheme/territory context needed for the other kind of label.

    Posters have another retrieval boundary

    The publisher documents a poster service separately from ordinary descriptive queries. A successful record response therefore does not prove that the applicable poster retrieval is available or has succeeded.

    Emby's Metadata Manager exposes image selection independently of the displayed title and overview. When only the image is missing, compare that asset route with the successful descriptive lookup rather than treating both as one failed search.
