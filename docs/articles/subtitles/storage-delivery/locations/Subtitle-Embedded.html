    Embedded subtitle tracks

    An embedded subtitle track is a separately described timed component inside a media container rather than permanent text in the video pixels.

    An embedded subtitle track is stored within a media container alongside video, audio and other tracks. It remains a separate timed component. A subtitle switch can therefore enable or disable it when the player supports that representation.

    Text already incorporated into video pixels is another case. It has no separately selectable subtitle track to remove.

    A container can describe several choices

    Track in an invented file Representation Role
    Video 1 Encoded pictures Main movie
    Subtitle 1 SRT-style UTF-8 text English dialogue
    Subtitle 2 PGS graphics English captions with sound descriptions

    Both subtitle tracks can share the video's programme timeline. Their language and title describe selection choices; their codecs describe how the chosen data is decoded and rendered.

    Merely storing an unused subtitle track does not mean it must be rendered. For an Emby comparison, inspect the selected subtitle, rather than treating every track in the file as an active processing requirement.

    Timing and configuration are container relationships

    The container describes track identity and applicable timestamps or durations. Codec-specific configuration can supply global styles, display geometry or other interpretation data.

    For Matroska's SRT mapping, the timed block contains UTF-8 cue text while container time and duration provide its interval. The standalone SRT counter and timestamp line do not need to appear as literal text inside that block.

    ASS can carry global script/styles as configuration. A graphics stream can use prior palette/object state. A raw packet dump without that context is not necessarily a complete independently playable subtitle.

    A track is not a font attachment

    A font resource can be stored separately from the timed track as a supporting container attachment. Retaining video, audio and ASS while dropping its intended fonts can preserve all timed track entries and still change the appearance.

    Track indices can also change during remuxing. Removing an earlier track can make “track 2” refer to another component. Language, title, codec and stable identifiers help compare the intended track across files.

    A supported remux can omit or retain a subtitle without reconstructing the video pictures. Rendering that subtitle into a new video is a different operation: it changes the pictures and introduces the video encoding work needed for the output.
