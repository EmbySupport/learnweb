    External subtitle files

    An external subtitle file is a separate subtitle resource associated with a media item through naming or other library metadata.

    An external subtitle lives beside or separately from the movie rather than inside its media container. A player or library associates that resource with the item, then reads and presents the chosen subtitle.

    That separation is useful when a translation is added or corrected: the video and audio file can stay intact while the subtitle resource changes.

    Association supplies information the format may omit

    Information Possible source
    Which movie or episode this file accompanies Filename association or a library record
    Language Naming, subtitle metadata or library metadata
    Content role, such as SDH or selected foreign dialogue Naming/flags and the actual contents
    Cue wording and intervals The subtitle file's own data
    Display styles or images The subtitle representation and its resources

    A simple SRT carries cue text and times, but does not inherently identify the exact movie edition. A language label is also not evidence that its sentences match the cut being played.

    Emby's naming documentation specifies the association and language/role conventions for external subtitles. Those are identification rules; they do not rewrite the cue times or inspect whether a translation is accurate.

    The timeline still belongs to the matching programme

    Suppose a sidecar's first line begins at 12.5 seconds. The player interprets it on the applicable movie timeline. Selecting the file does not automatically discover a missing opening logo and add an offset.

    A different release can have the same title and language but an extra scene. The resulting edition mismatch can require different corrections in different sections, even though the library found the file successfully.

    Replacing a sidecar likewise does not imply that every active viewing session has already loaded the replacement. Resource discovery and the bytes currently being consumed are distinct observations.

    Some external presentations use companion resources

    VobSub commonly uses a binary SUB plus an IDX carrying indexing/configuration. Styled text can depend on fonts. “External” does not mean “one self-contained text document.”

    When those resources are needed, they must be available to the consumer that interprets the presentation. Providing an index but not its binary data, or a named font without a usable face, leaves a different missing boundary.

    An Emby route can deliver the selected sidecar in an accepted representation or render it upstream when required. The external location makes the file separately manageable; format and client capabilities determine how it becomes visible.
