    Time Bases

    A timestamp value of 45,000 does not mean 45,000 seconds. It needs a scale. If the stream's time base is 1/90000, each tick lasts one ninety-thousandth of a second, and 45,000 ticks means half a second.

    time in seconds = timestamp × time base
45,000 × (1/90,000) = 0.5 seconds

    Different tracks can use different scales while referring to the same moment:

    Time base Timestamp Time in seconds
    1/90000 45,000 0.5
    1/48000 24,000 0.5
    1/1000 500 0.5

    These are illustrative scales, not a rule that every audio or video track must use one of them.

    A time base is not a frame rate

    A stream at 25 frames per second might advance by 3,600 ticks per frame on a 90,000-tick scale. Its time base is still 1/90000, not 1/25. Variable-frame-rate video can advance by different amounts while keeping one time base.

    When remuxing, software may rescale timestamps into the destination container's units. Larger integer values after the operation do not mean the movie became slower.

    For an Emby synchronization investigation, compare timestamps converted to seconds. ffprobe reports values such as pts_time and dts_time for this purpose. The raw integers from two tracks are not directly comparable until their scales have been applied.

    A nonzero starting timestamp is not automatically an error either. The relative alignment of the tracks and the presentation's start handling determine what the listener sees and hears.
