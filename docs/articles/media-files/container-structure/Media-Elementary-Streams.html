    Elementary Streams

    An elementary stream contains one coded media component before it is combined with other components in a container.

    After a demuxer opens a movie, the video decoder receives encoded video rather than the entire movie file. That one coded component is an elementary stream. Its codec syntax describes how to reconstruct the media; the outer container supplies additional presentation organization.

    For AVC/H.264, the elementary data contains units such as sequence configuration, picture configuration, and coded slices. The decoder interprets these to reconstruct pictures and maintain the reference state needed for later pictures. The elementary stream is thus structured data, even without a container around it.

    Encoded picture, packetized picture, transport packets

    These three layers are easy to confuse:

    Layer What is added or described
    Elementary stream Codec configuration and encoded media syntax
    Packetized elementary stream, PES MPEG systems framing that can include presentation and decoding timestamps
    MPEG transport packets Small fixed-size units carrying pieces of PES data or signalling, identified by PID

    A PES packet can span many transport packets. Neither boundary necessarily marks one independently displayed picture. Demultiplexing transport stream removes the delivery structure to recover the appropriate component and its timing.

    What happens when the component is extracted?

    Consider variable-frame-rate video whose first pictures are meant to appear at 0, 40, and 100 milliseconds. An extraction that retains only coded picture data may lose the container's distinction between the 40-millisecond and 60-millisecond gaps. If a later tool assumes evenly spaced 25 fps pictures, it would schedule them at 0, 40, and 80 milliseconds instead.

    Whether timing survives depends on the codec data, extraction format, and writing tool. The example shows why “the encoded picture bytes were copied” and “the presentation was preserved” are different observations.

    A container also carries language, track selection, subtitles, and chapters outside the video elementary stream. Extracting video alone omits those components by definition. For a usable Emby library copy, remuxing into a suitable container normally retains more of the presentation than a raw extraction does.

    Framing can change without picture decoding

    An AVC unit needs an identifiable boundary. One packaging convention prefixes a start code; another prefixes a byte length. A bitstream filter can translate that framing and move configuration to the required place. It does not need to reconstruct and re-encode each picture to do so.

    When investigating an extracted source, ask which layer the tool wrote and which information that layer actually retains. That makes a missing timeline or track description an identifiable result of extraction, rather than a mysterious change in the codec.
