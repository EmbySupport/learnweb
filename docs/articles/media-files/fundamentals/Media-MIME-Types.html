    Media MIME Types

    An HTTP response can announce Content-Type: video/mp4. That label is a media type, commonly called a MIME type. It helps the receiving software interpret the content before examining the bytes.

    The type has two parts: video is the top-level category and mp4 is the subtype. Some types also define parameters that describe the contents more precisely.

    Label What it communicates
    video/mp4 MP4-family content containing video
    audio/mp4 MP4-family content containing audio without video
    audio/mpeg MPEG audio content
    application/vnd.apple.mpegurl An HLS playlist, not the encoded movie itself

    The registered meanings come from IANA and the relevant format specifications. Labels used in older software can differ.

    A label is only part of compatibility

    A generic container type does not establish which codecs the client can decode. The standardized codecs parameter can provide more detail, but the actual media must still match what the sender declares.

    For Emby playback through a browser or another HTTP-based app, the delivered response type concerns what the server sends. It can differ from the original library file when the server repackages or converts the media.

    An incorrect Content-Type can affect how a browser handles a resource even when the file is valid. Changing the label, however, does not convert the data. Investigate it alongside the actual container and codecs, rather than treating it as a replacement for inspection.
