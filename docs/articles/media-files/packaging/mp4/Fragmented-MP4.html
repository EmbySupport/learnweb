    Fragmented MP4

    A live presentation cannot wait until its final frame exists before describing the entire movie. Fragmented MP4, often shortened to fMP4, solves that packaging problem by describing successive portions of the media as they become available.

    The initial information identifies tracks and codec configuration. Each movie fragment then describes samples associated with its media data.

    Original schematic of a common streaming layout. Optional boxes are omitted; fragments need not have equal durations.

    The key boxes are moof, the movie-fragment description, and mdat, its encoded media. For browser Media Source Extensions, the W3C byte-stream note defines initialization and media-segment rules built on these structures. HLS also defines an fMP4 segment format.

    A fragment is not automatically a standalone movie

    A media fragment can depend on the initialization information for its codec description. Decoding can also depend on earlier pictures unless the fragment begins at a suitable random access point. Copying one downloaded fragment into a new file therefore does not necessarily produce something independently playable.

    Fragmentation describes the internal structure. It does not require one physical file per fragment: a fragmented presentation can be stored in a single file or delivered through separate segments.

    For an Emby playback investigation, distinguish the original library file from the package delivered to the app. A streaming path may use segmented media even when the source is a conventional MP4 or another container. The source extension alone cannot reveal that delivery structure.

    Unlike fast start, fragmentation repeatedly supplies sample information. Neither method changes the codec or encoded picture quality. Compatibility still depends on the chosen codecs and the player's support for the particular streaming conventions.
