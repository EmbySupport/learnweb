    MP3 Files and MPEG Audio Frames

    An MP3 file is usually a sequence of MPEG audio frames rather than a general container holding many tracks. Each frame has a small header that helps the reader identify its encoding and boundaries.

    This file framing is distinct from the MP3 codec's compression method. The codec determines how the sound is represented; the file also needs a way to carry the resulting frames and useful descriptive information.

    MP3 file information What it contributes
    MPEG audio frame header Version, layer, bitrate, sample rate, and channel mode
    Encoded frame data Compressed audio information
    ID3 tags, when present Track descriptions and optional artwork
    Optional Xing or VBRI information Frame counts or navigation information useful for variable-bitrate files

    ID3 also calls its metadata items frames. An ID3 title frame is not an MPEG audio frame and contains no block of decoded music samples.

    Variable bitrate complicates simple estimates

    Estimating duration from file size and one observed bitrate can give a misleading duration for a variable-bitrate MP3. The reader can use frame counts, optional navigation information, or a fuller examination of the stream instead.

    MP3 Layer III also uses a bit reservoir, allowing encoded data associated with a frame to draw on bytes carried earlier. Cutting at an apparent frame boundary does not guarantee clean independent decoding from that point.

    In an Emby music collection, missing or unusual tags can affect identification while the audio plays normally. Incorrect duration or seeking can point to a different problem with frame information or navigation. Keep those symptoms separate.

    When a file is rewritten, verify the tags and seek behaviour along with the sound. Copying the compressed audio is a different preservation task from retaining album information, artwork, or accurate navigation.
