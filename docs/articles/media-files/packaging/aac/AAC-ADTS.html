    AAC: Audio Data Transport Stream (ADTS)

    A file ending in .aac often uses Audio Data Transport Stream (ADTS) framing. ADTS puts a header before encoded AAC data, letting a reader find frame boundaries and discover important audio properties as it reads.

    It is an audio framing format. It is not the same thing as MPEG transport stream, although ADTS-framed AAC can be carried within TS.

    ADTS header information What it helps the reader do
    Synchronization pattern Locate a candidate frame boundary
    Frame length Determine how many bytes belong to the frame
    Core profile and sampling-frequency fields Establish basic decoder information
    Channel configuration Describe the core channel arrangement or signal further configuration

    A common single-block ADTS frame has a seven-byte header without CRC protection, or nine bytes with it. The header's synchronization pattern is a clue for parsing; validating lengths and successive frames is more reliable than treating one matching byte pattern as proof of a valid file.

    A header is not a complete codec description in every case

    More advanced AAC tools can require additional signalling in the audio data. With HE-AAC, for example, the final decoder output properties can differ from those described for the core. Read the complete probe result rather than inferring every property from one header field.

    For an Emby import, an ADTS AAC file and an AAC track in M4A may ask the same audio decoder to handle the sound, while using different readers to supply it. Moving between those packages can be possible without recompression.

    Such a move must translate the configuration and remove or add the appropriate framing. Renaming .aac to .m4a does neither. A general MP4 also supplies track timing and metadata structures that a bare ADTS stream does not provide in the same way.
