    Overview: Media files and containers

    Media files combine encoded tracks with container structures that organize playback, timing and metadata.

    A filename such as Film.mkv identifies a kind of packaging; it does not tell you every codec, language or subtitle track inside. A useful description of the file separates its container, its streams and the information that lets a player find and present them.

    The fundamentals establish that vocabulary. Container and packaging topics explain the structures behind seeking, delivery and alternate tracks, while inspection tools reveal what a particular file actually contains. Playlists and references cover the related case where a small file points to media elsewhere. These distinctions help explain why two similarly named files can take different playback paths in Emby.

    • Media file fundamentals
      Media-file fundamentals distinguish the stored object, its encoded tracks and the terms used to describe its contents.

    • Container structure
      Container structures organize encoded streams, timing, track information and navigation within a media file.

    • Common containers
      Media container families define different ways to package tracks, metadata and navigation information.

    • File packaging details
      Media packaging details shape how a container stores, exposes or references the content needed for playback.

    • Media inspection
      Media inspection reads the properties and stream structure needed to understand a particular file.

    • Playlists and media references
      Playlists and media references describe locations or playback organization rather than storing the complete referenced media.
