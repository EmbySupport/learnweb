    Media Stream Inspection with MediaInfo

    MediaInfo is useful when “this file will not play” needs to become a more precise description. Open the file and use a detailed view, such as Tree or Text, to see the container and each media track separately.

    Read the report from the outside inward:

    Report section Useful questions
    General Which container is it, how long is it, and what is the overall bitrate?
    Video Which codec, profile, dimensions, bit depth, and color signaling are present?
    Audio Which codec, language, channel arrangement, and sample rate belong to each track?
    Text Which subtitle format and language does each track use?
    Menu, when present Which chapters or navigation entries were detected?

    Field availability depends on the file and the version of the tool.

    Bring the right details to a playback question

    For Emby troubleshooting, a text report is more useful than a screenshot showing only the extension and resolution. Keep the sections for the selected audio and subtitle tracks, because another track can change the playback requirements.

    MediaInfo's Format and Codec ID fields serve different purposes. “HEVC” names a coding system; hvc1 identifies a particular container representation. Both can matter when players disagree about compatibility.

    Color and HDR metadata fields describe information detected in the source. They do not show the display's active output mode or prove that the entire playback route preserved that information.

    MediaInfo is an inspector, not a decoder test or repair tool. If a film fails at one scene, a normal-looking summary does not rule out damage there. Include the failing time and playback method alongside the report, and use ffprobe when packet or timing details are needed.
