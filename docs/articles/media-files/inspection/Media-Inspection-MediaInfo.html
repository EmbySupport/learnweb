    Media Stream Inspection with MediaInfo

    An Emby playback question often starts with “this is a 4K MKV.” MediaInfo can turn that shorthand into a description of what the file actually asks a reader and decoder to handle.

    Use a detailed presentation such as Tree or Text, then read from the outside inward. The General section describes the package; each Video, Audio, or Text section describes a component inside it.

    Section Details to retain for a playback comparison
    General Format, duration, file size, and overall rate
    Video Codec, profile, dimensions, sample format, and color information
    Each Audio Codec, channels, sample rate, language, and title
    Each Text Subtitle format, language, and selection information
    Menu, where detected Chapter or navigation positions

    Read two fields together

    Imagine the video section says Format: HEVC and Codec ID: hvc1. HEVC names the compression system, while hvc1 identifies the container representation. They describe different layers of one track.

    Now add Main 10 and 3840 × 2160. That suggests a 10-bit-capable HEVC profile and a particular raster, but leaves frame rate, level, precise sample format, and the receiving decoder path to examine. Rather than collecting one label, build the complete description that explains a difference between files.

    A second file with the same General format can have a different video profile, a different soundtrack, or different subtitles. The section boundaries keep those differences visible.

    Choose the component that actually played

    If the source contains English surround audio and English stereo commentary, retain both descriptions and identify the session's selection. A report for the unselected surround track cannot explain the processing of the commentary track.

    The same principle applies to subtitles. Their format can change rendering or conversion work even when the video is identical. Keeping the relevant sections in a text report is more useful than a screenshot of only resolution and filename.

    HDR fields describe the source information that MediaInfo detected. The display's current output mode is measured elsewhere. In a comparison between direct and converted playback, first establish the source's signaling, then obtain evidence about the delivered output and display.

    Understand the report's scope

    MediaInfo can show declared values, calculated values, or information derived by analyzing media. Different field names, rounding, or analysis versions can explain some disagreements with another inspector. The report is also not an exhaustive decode of the entire file.

    For a repeatable failure at a scene, retain the report as the source description and add the failing position and selected playback route. Packet or frame inspection can then examine the particular timing or decoding question that the summary cannot answer.
