    Media Stream Inspection with ffprobe

    ffprobe is FFmpeg's inspection tool. It reads media information and reports it as text or structured data; it does not re-encode the input.

    With ffprobe installed and available on the command path, this produces a JSON report:

    ffprobe -v error -show_format -show_streams -show_chapters -of json "Movie.mkv"

    The three requested sections separate whole-file information, individual tracks, and chapters. Missing fields mean the tool did not report a value, not necessarily that the underlying property is zero.

    Output field How to read it
    format_name The detected demuxer or format family; it can list related formats
    codec_name / codec_type A track's codec and whether it is video, audio, or another type
    time_base The scale used for that track's integer timestamps
    tags / disposition Reported metadata and selection flags
    duration / bit_rate Reported or estimated values at the relevant scope

    Examine the part that matches the problem

    For a transport-stream recording, add -show_programs to see programme groupings. For timing, request packets from a short interval:

    ffprobe -v error -select_streams v:0 -read_intervals "%+5" -show_packets -show_entries packet=pts_time,dts_time,duration_time,flags -of json "Movie.mkv"

    This selects the first video stream and examines an interval of approximately five seconds from the initial read position. Packet durations and reordering mean the result need not correspond to exactly five seconds of displayed pictures.

    For Emby troubleshooting, use the same source file and record the selected tracks. Compare timestamp values in seconds and avoid mistaking a demuxer family name for a precise file subtype.

    A summary probe does not decode every frame. Packet inspection can reveal timing clues, but a full integrity investigation may need decoding as a separate step.
