    AVI Container

    AVI, short for Audio Video Interleave, is a longstanding container for audio and video. Its RIFF-based structure divides the file into chunks, with stream descriptions near the beginning and encoded media in a media-data list.

    An old AVI may contain MPEG-4 Part 2 video and MP3 audio; a capture AVI may contain DV or uncompressed media. None of those codecs is defined by the .avi extension itself.

    AVI component Purpose
    Header list, hdrl Describes the file and its streams
    Media list, movi Holds interleaved stream chunks
    Indexes, such as idx1 or OpenDML indexes Locate media chunks for navigation

    OpenDML extensions allow AVI to handle larger files and provide extended indexing. That is different from assuming every legacy AVI reader understands every extension.

    Why the index is worth noticing

    A file can sometimes play sequentially while seeking badly because its index is absent or damaged. Rebuilding an index may improve navigation, but it cannot restore missing media or repair the encoded contents of a broken chunk.

    AVI also predates many modern delivery conventions. It is a less natural fit for some combinations of advanced codecs, per-sample timing, and subtitle features than newer containers. A successful mux is not proof that every target player will interpret the result as intended.

    For an AVI in Emby, start with stream inspection. If the app can decode the video but needs a different package, a remux may be enough. If the selected codec itself is unsuitable, changing AVI to MP4 or MKV while copying the stream will leave that limitation in place. Check synchronization and seeking as well as the first few seconds of playback.
