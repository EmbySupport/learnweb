    WAV and RIFF

    A .wav is often uncompressed PCM, but WAV is a file format, not a promise about the encoding. The format description inside the file tells a reader how to interpret the audio data.

    The familiar structure uses RIFF, a system of identified chunks, with WAVE as its file type. RIFF also underlies other formats such as AVI; that does not make an AVI an audio file.

    WAV component What it contains
    RIFF/WAVE header Identifies the overall file structure
    fmt chunk Audio format, channels, sample rate, and related parameters
    data chunk Encoded or uncompressed audio data
    Additional chunks Optional metadata or other supporting information

    A reader should follow the chunk structure instead of assuming all WAV headers have one fixed length. Metadata or an extended format description can move the start of the audio.

    PCM needs more than a sample rate

    For linear PCM, sample precision, integer versus floating-point representation, and byte layout matter. Multichannel WAV commonly uses WAVEFORMATEXTENSIBLE, which can describe speaker positions and distinguish valid bits from the space occupied by each sample.

    That makes a channel count insufficient to establish channel order. Six channels need the correct roles as well as six sets of numbers.

    When checking a WAV for an Emby music library, inspect those properties and the actual encoding. Two files at the same sample rate can differ in precision, channel layout, and decoder requirements.

    Classic RIFF uses 32-bit chunk sizes, creating a practical size limit near 4 GiB. Large-file variants such as RF64 use additional conventions; renaming a large file .wav does not teach an older reader to understand them. CAF is another format designed to avoid that classic size constraint.
