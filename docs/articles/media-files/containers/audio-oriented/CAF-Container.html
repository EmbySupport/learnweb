    CAF: Core Audio Format

    A long recording can run into the size conventions of classic WAV or AIFF before the recording software runs out of disk space. Core Audio Format (CAF) was designed to avoid that limitation while accommodating different audio encodings.

    CAF is Apple's chunk-based audio container. It uses 64-bit chunk sizes and can represent both uncompressed samples and packet-based compressed audio. The .caf extension therefore describes the package, not one particular sound format.

    CAF information Its purpose
    Audio description Defines encoding, sample rate, and other audio properties
    Audio data Contains the actual samples or encoded packets
    Packet table, where needed Describes variable packets and valid audio length
    Channel layout and metadata chunks Describe speaker roles and supporting information

    Some codecs produce packets of varying size or duration. A packet table lets the reader connect those packets to usable audio instead of guessing from the overall file size.

    An editing file is not automatically a delivery file

    CAF's flexibility is valuable in capture and production workflows, including recordings that grow while they are being written. It does not imply that every music player implements every CAF encoding or optional feature.

    If material from such a workflow is intended for an Emby collection, inspect the audio format first. The useful decision is which encoding and container the intended listening app can handle, while retaining the precision and channels that matter for that recording.

    WAV, AIFF, and CAF can all store uncompressed audio. Switching between them does not inherently improve its sound. A container change can preserve samples, but conversion settings may also resample or alter their precision, and metadata can need separate handling.

    Keep the original production file until the listening copy has been checked for complete duration, expected channels, and correct descriptive information.
