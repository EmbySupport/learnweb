    Ogg Container

    Ogg is a container, while Vorbis and Opus are audio codecs that can use it. When someone says an .ogg file is Vorbis, they are describing a common combination rather than defining every Ogg file.

    Ogg groups codec packets into pages. A packet may fit inside one page or continue across pages. Each logical stream has its own serial number, allowing the reader to keep its packets together.

    Ogg field or structure Why it matters
    Page capture pattern Helps identify page boundaries
    Stream serial number Identifies the logical stream
    Page checksum Detects changes in that page's data
    Granule position Supplies position information interpreted by the codec mapping

    The granule position is not a universal millisecond timestamp. Its meaning comes from the mapping for the codec carried by the stream. For example, Opus has specific rules for start trimming, seeking, and the final sample position.

    The same container can carry different audio

    A music file using Vorbis and an .opus file using Ogg Opus require different decoders even though both use Ogg pages. Inspect the codec when comparing their behaviour in an Emby app. Packaging recognition is only part of the playback decision.

    Ogg also permits chaining: one logical stream can finish and another begin within the same physical file. That is useful for concatenated or continuous material, but software may differ in how it presents the resulting duration, track changes, or seeking.

    A page checksum can reveal a damaged page; it does not correct the damage or establish that all audio decodes successfully. If a file reports an odd duration or fails after a particular point, compare its probe information with actual playback through that transition.

    Keep the container, codec, and stream layout together in a report. The .ogg extension by itself leaves all three questions partly unanswered.
