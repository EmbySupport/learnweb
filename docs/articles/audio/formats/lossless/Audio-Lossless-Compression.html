    Lossless Audio Compression

    Lossless compression changes how audio is stored, not the sample values recovered by decoding. For supported source data, the decoder reconstructs exactly the values supplied to the encoder.

    Audio samples often have predictable relationships. An encoder can store a prediction and the remaining error more efficiently than a full value for every position. The error is retained completely, so even an imperfect prediction can be reversed.

    A small example

    Suppose the samples are 100, 104, 107, and 109. Predicting each value from the previous one gives:

    Stored item Value Reconstructed sample
    Starting sample 100 100
    Difference +4 104
    Difference +3 107
    Difference +2 109

    This is an illustration, not the complete algorithm of a particular codec. Real encoders use more sophisticated predictions and efficient integer coding.

    What “exact” applies to

    Converting the same supported PCM samples between FLAC and ALAC can preserve the audio. Tags, artwork, container headers, and file bytes may nevertheless change. Compare decoded samples when checking audio equality, rather than expecting the two files to have identical checksums.

    A compression setting normally trades encoding effort against file size. It does not make a lossless decoder restore a better or worse version of the samples.

    There are also two limits to the promise. A lossless copy of decoded MP3 audio cannot recover the pre-MP3 source. And a lossless file played through resampling, downmixing, or volume processing need not reach the output unchanged.

    In Emby, delivery conversion and the client's output are therefore worth checking separately from whether the stored codec is lossless.
