    Audio-Description Tracks

    A character silently hides a key under a flowerpot. The main soundtrack offers a rustle but no words explaining the action. Audio description adds the missing visual information, helping a listener who is blind or has low vision follow why that action matters later.

    The description is authored as part of the listening presentation. Making dialogue louder or transcribing its words does not supply an unspoken visual event.

    Fit useful description into the programme

    Descriptions can identify actions, expressions, scene changes, on-screen text, and other important visual details. They are generally placed around dialogue and significant sound where possible.

    The aim is enough information to understand the programme, not narration of every visible object. A complete described mix balances that narration with dialogue, music, and effects so they remain usable together.

    Identify the role, not just the language

    Illustrative track title Intended content
    English — Main Ordinary English soundtrack
    English — Audio Description Programme with important visual details described
    English — Commentary Discussion by creators or other commentators

    All three can have the same language code. Descriptive track names or role signaling tell the listener which presentation to select. A commentary is not a substitute for audio description merely because it adds speech.

    In an Emby library, preserving useful language and track-role information makes these choices distinguishable without listening to each track to discover its purpose.

    Complete described mix versus narration component

    A movie file can contain a fully mixed alternative soundtrack. Selecting it supplies the description and programme together, regardless of whether that mix is stereo or surround.

    Broadcast systems can instead carry associated narration that a capable receiver combines with the main audio. This supports the defined balance or control behavior, but the narration component alone may lack the movie's dialogue, music, and effects.

    That structural difference matters during conversion:

    1. Identify whether the source provides a complete described track or a supplementary component.
    2. If supplementary, assemble the intended presentation using its mixing/signaling rules.
    3. Preserve the resulting accessible mix, or preserve the component structure for a reader that supports it.
    4. Retain labels that make the accessible choice discoverable.

    Simply extracting an associated narration component can create a recording of descriptions without a complete programme soundtrack. Copying only the main track can remove the accessibility option entirely.

    Check the option as content

    Verify a few places where description is expected, its balance with dialogue, and the full intended duration. Then verify track selection and names in the listening app.

    These checks answer different questions from successful codec decoding. A perfectly playable main mix may still be the wrong presentation for the listener, while a complete described mix preserves information that neither louder dialogue nor another codec can generate.
