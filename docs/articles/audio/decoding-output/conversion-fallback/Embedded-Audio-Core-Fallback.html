    Fallback to an Embedded Audio Core

    An embedded core is an existing compatible part of an audio stream that a less capable decoder can use. Falling back to it can keep sound playing without re-encoding the full presentation.

    The common example is a DTS-HD disc soundtrack containing a DTS core. A core-only decoder uses the lossy compatible presentation; a full decoder can also use extension information.

    Operation Where the fallback audio comes from
    Embedded core fallback An already encoded component inside the stream
    Selecting another audio track A separately stored presentation
    Audio transcoding A new encoding made from decoded audio

    These operations can produce similar receiver labels while having different origins.

    A core does not preserve every enhancement

    A DTS core from a Master Audio track is not the lossless Master Audio result. It can also lack additional channels or immersive information available through the full presentation. The benefit is compatibility without another encoding generation, not preservation of all source features.

    Do not assume that every DTS-HD stream has a core: the format also allows extension-only arrangements.

    The Dolby case is different. TrueHD may be accompanied by an AC-3 fallback in disc packaging, but TrueHD itself does not contain a DTS-style lossy AC-3 core. E-AC-3 independent substreams are also not automatically AC-3 components.

    In an Emby session, confirm what the file actually contains and what was delivered. If a core is selected or extracted, compare that result with the full source presentation. If the server creates another codec, that is transcoding, even if the new track happens to use the same familiar codec name as a typical fallback.
