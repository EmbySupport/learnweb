    Decoded PCM Output

    When a receiver displays PCM, it is receiving sample values rather than being asked to decode the file's original compressed codec. The player or an earlier component has already reconstructed the audio.

    This can be the normal result of playing a lossless soundtrack. Decoding FLAC or a supported TrueHD presentation to PCM does not itself introduce lossy compression.

    What to check Why it matters
    Output channel count and layout Confirm whether the intended speaker presentation survived
    Output sample rate Identify any rate conversion
    Valid sample precision Separate audio precision from storage-word size
    Volume, mixing, and effects Identify processing applied after decoding

    A 24-bit signal can travel in a 32-bit storage word, so those two numbers need not match. Similarly, a high-rate PCM output can contain resampled lower-rate content rather than a high-rate original recording.

    PCM does not identify the source

    Both lossy and lossless decoders produce PCM. A receiver's PCM label therefore cannot tell you whether the library file was MP3, FLAC, or another codec.

    Ordinary channel PCM also does not carry the original object-position metadata of an immersive bitstream. A supported player can first render an immersive mix into output channels, or use a metadata-bearing path such as Dolby MAT. Those are different results.

    In an Emby session, compare the selected source, server delivery, and actual PCM output. A change from 7.1 to 2.0 needs investigation; a change from a compressed format's name to PCM can simply show that decoding happened in the player.
