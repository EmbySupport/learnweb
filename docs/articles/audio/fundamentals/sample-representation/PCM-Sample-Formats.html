    PCM Sample Formats

    “PCM” tells you that audio is represented by sample values. A PCM sample format tells you how to interpret those values: integer or floating point, their storage size, and sometimes their byte order.

    This becomes useful when a log shows a name such as s16 or fltp. These are FFmpeg's names for working sample formats, not additional audio codecs.

    FFmpeg format Meaning
    s16 Signed 16-bit integer samples, interleaved
    s32 Signed 32-bit integer storage, interleaved
    flt 32-bit floating-point samples, interleaved
    fltp 32-bit floating-point samples, separate plane per channel

    Interleaved stereo stores successive frames as left, right, left, right. Planar stereo keeps the left samples in one plane and the right samples in another. Correct conversion between those arrangements changes where the values live, not what the listener hears.

    Storage size is not always signal precision

    A decoder can place 24-bit audio in 32-bit integer slots. The extra storage bits do not establish that the source contains 32 bits of useful precision. Similarly, an s32 line in a processing log does not by itself tell you the original bit depth.

    Floating-point processing commonly treats −1 to +1 as the nominal full-scale range. It can represent intermediate values beyond that range, but the eventual output still has limits. A later conversion or output stage can clip if those values are not brought back into range.

    For stored PCM, endianness describes the order of bytes within each multibyte sample; it is separate from channel order. Misreading either arrangement can produce severely wrong sound even though every byte arrived intact.

    Emby playback and transcoding logs may show a decoder's working format. A change from an encoded soundtrack to floating-point samples is a normal processing step, not evidence that the file itself was stored as floating-point PCM.
