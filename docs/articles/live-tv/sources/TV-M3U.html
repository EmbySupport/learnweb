    Extended M3U channel lists

    An extended M3U channel list associates source URLs with channel labels and attributes, while actual stream access and programme timing remain separate operations.

    An extended M3U channel list can describe live sources through text entries: a channel label and attributes are associated with the following source URL.

    Emby’s M3U tuner documentation describes accepting this source inventory through a file or downloadable list. Reading the list and acquiring its channels are separate operations.

    Two original channel entries

    #EXTM3U
#EXTINF:-1 tvg-id="harbour.news" tvg-name="Harbour News" tvg-chno="101" tvg-group="News",Harbour News
https://tv.example.net/live/news
#EXTINF:-1 tvg-id="harbour.cinema" tvg-name="Harbour Cinema" tvg-chno="205" tvg-group="Films",Harbour Cinema
https://tv.example.net/live/cinema

    The hosts, identifiers and entries are fictional. No endpoint was requested.

    The negative duration placeholder is a live-channel-list convention in this teaching example, not the duration of an actual programme or an HLS media-segment instruction.

    Extended IPTV attributes are conventions interpreted by an implementation; they are not all defined by one universal normative M3U standard.

    Attributes have different roles

    Attribute Documented Emby role relevant here
    tvg-id Channel identity
    tvg-name Channel name
    tvg-chno Channel number
    tvg-group Channel group/tag relationship
    tvg-shift A guide-time offset when specifically applicable

    The label after the comma is another presentation name in the entry. The URL on the next line supplies the source location.

    A parser must preserve quoted attribute values containing spaces. Splitting the metadata line on every space would break tvg-name="Harbour News" into unrelated pieces.

    Guide matching can use the channel identity, while the number and name control other aspects of presentation. Renaming “Harbour News” does not inherently change harbour.news.

    A quoted comma is not the metadata boundary

    Use a separate original metadata-line exercise:

    #EXTINF:-1 tvg-id="harbour.news" tvg-name="Harbour News, Coast",Harbour News, Coast

    The comma inside the quoted tvg-name belongs to that attribute value. The comma after the closing quote separates metadata from the presentation label.

    A naive split at the first comma would stop inside the quoted attribute. A parser of this declared example must track the quote state before choosing the boundary.

    The intended attribute value and presentation label are both “Harbour News, Coast”; the identity remains harbour.news. This is a text-parsing exercise, not a report that every playlist implementation accepts every extension convention.

    A channel URL is not a successful media response

    The list can be syntactically readable while a source later needs a supported request context, authorization or available session.

    An expired or changed URL can fail independently of the channel’s display metadata. A successful HTTP response can also contain an error document rather than the intended encoded media.

    IPTV connection limits adds another condition. The number of entries in a list does not establish the permitted number of simultaneously opened channels.

    HLS playlists describe another object

    An HLS media playlist describes media segments and their sequence for a presentation. The two entries above describe different channel sources, not two consecutive segments of one movie.

    A channel URL could lead to an HLS presentation whose own playlist then supplies the media timeline.

    RFC 8216 defines the HLS semantics; HLS playlists develops their use. Sharing #EXTM3U notation does not make all channel-list attributes into HLS tags.

    Identity should survive presentation edits

    An original parser of the example should retain two identities: harbour.news and harbour.cinema, with their corresponding numbers and URLs.

    Changing the first display label to “Harbour News HD” while retaining its identity leaves it the same source entry under that declared model. Changing the identity or URL instead changes a different relationship.
