    Dolby Vision RPU Metadata

    RPU is the name you often see beside Dolby Vision video in media reports. It carries Dolby Vision metadata; it is not an additional movie image or an audio track.

    The metadata can describe picture characteristics and processing instructions. Depending on the content and metadata version, it can include analysis, target-display trims, and the active picture area.

    Information in the Dolby Vision workflow Why it matters
    Scene analysis Describes the picture being adapted
    Creative trims Adjusts the mapped appearance for a target
    Active-area information Distinguishes the picture from surrounding letterbox regions

    The RPU must remain associated with the correct frames. A useful thought experiment is an edit that removes the first second of video but keeps the old metadata timing: the instructions no longer describe the pictures receiving them. Dolby's authoring guide identifies out-of-sync metadata as a possible cause of unexpected brightness changes.

    In HEVC delivery, the metadata is carried in special units alongside the encoded picture. A media report showing BL+RPU therefore means a base layer plus metadata, not two image layers. BL+EL+RPU adds an enhancement layer.

    When examining an Emby playback issue, an RPU-present flag establishes that metadata was detected in the source. It does not prove that the player used it, that it is synchronized, or that the full output path supports that Dolby Vision profile.

    The metadata also cannot simply be borrowed from another release because its title matches. Different edits, frame timing, framing, or grades can break the relationship between the information and the picture.
