    Dolby Vision Profile 8

    Dolby Vision Profile 8 combines a single ten-bit HEVC picture layer with metadata and a specified compatible base signal.

    A report says Profile 8.1 and dvhe.08.06. Those fields can agree: one describes base compatibility, while the full string identifies Profile 8 and Level 6.

    Profile 8 uses one ten-bit HEVC picture layer plus Dolby Vision metadata. It has no Dolby Vision picture enhancement layer. The current public profile definition lists these compatible base forms:

    Common shorthand Base interpretation
    8.1 HDR10-compatible
    8.4 HLG-compatible

    What changes between the two base forms?

    The HDR10-compatible form has a PQ-based light interpretation. A supported ordinary HDR10 route can use that base without completing the Dolby Vision presentation.

    The HLG-compatible form has a relative scene-light system relationship. Its appropriate fallback is HLG processing, not reinterpretation as PQ. HLG explains how display adaptation participates in that system.

    The compatibility number after the point identifies this base arrangement. It does not replace the level, which supplies processing bounds. Keeping both fields matters when selecting a playback path.

    HLG fallback for camera recordings

    A personal-video source can carry an HLG-compatible base with Dolby Vision information. A suitable Dolby Vision route processes the prepared presentation using the applicable metadata. A suitable HLG route can use the defined base interpretation instead.

    The same decoded signal values do not imply the same absolute light in the two named systems without their respective rendering operations. That is why a broad HDR badge gives less useful diagnostic information than the transfer and compatibility fields.

    Apple's HDR video metadata guidance describes these relationships in camera-originated content. For an Emby library, inspect the actual recorded stream rather than assuming every Dolby Vision file uses the same base as a UHD Blu-ray title.

    Keep single-layer delivery separate from conversion history

    Profile 8's one picture layer differs from Profile 7's base-plus-enhancement arrangement. A file prepared from Profile 7 can change what reconstruction information remains available, even when its copied base is still a valid picture.

    During playback, follow the source, server-delivered stream, and app/output interpretation. That record shows whether the session uses Dolby Vision, an HDR10 or HLG base, or a separately converted output.
