    Dolby Vision Profile 20

    Dolby Vision Profile 20 supports stereoscopic delivery using Multiview HEVC and additional Dolby Vision playback requirements.

    A stereoscopic presentation needs the correct picture for each eye as well as the intended brightness and color rendering. Dolby Vision Profile 20 combines these requirements using ten-bit Multiview HEVC for its 3D form and additional Dolby Vision metadata processing.

    Decoded views and left/right eye assignment

    The 3D stream uses codec layers for distinct views of the scene. The base view and the additional view are decoded with their multiview relationship. The layer-to-eye association identifies which view belongs to the left or right eye; correct assignment is part of producing the intended depth.

    This arrangement differs from side-by-side packing of two reduced-width views in one ordinary frame. It also differs from Profile 7's base and enhancement residual. A second eye view represents another viewpoint, while an enhancement residual supplies reconstruction information for a picture.

    A supporting route therefore has to perform several connected jobs:

    1. Read the multiview packaging and configuration.
    2. Decode the required HEVC views and their dependencies.
    3. Use the signaled eye assignment.
    4. Process the required Dolby Vision information.
    5. Deliver the views and presentation to the selected output.

    Each stage can affect the result independently. Successfully showing one ordinary HEVC view is useful codec evidence, but does not establish the complete stereoscopic path.

    Check the additional presentation information

    The public profile notes require Profile 20 playback devices to consume display-management version 4 metadata, including L8 target trims. Those requirements extend beyond the mandatory metadata support of some other Dolby Vision profiles.

    For stereoscopic content, the notes also specify a reference-display information message that associates layers with eyes. The Dolby Vision level applies to each view layer. A source record needs these structural facts alongside its codec and profile to describe the required path.

    Distinguish the defined forms

    Form or property Meaning
    3D Ten-bit MV-HEVC views for stereoscopic presentation
    2D A defined ten-bit HEVC form
    Base compatibility ID 0 Dolby Vision-specific base interpretation
    Base compatibility ID 4 HLG-compatible base interpretation

    The specification describes 2D Profile 20, while its public notes do not require every approved Profile 20 playback device to play that 2D form. Inspect support for the actual content form rather than inferring it from the general profile badge.

    An HLG-compatible base identifies its light interpretation. It does not resolve multiview packaging, codec dependencies, or eye assignment for an ordinary HLG television. Those are separate jobs in the route above.

    For an Emby investigation, record whether the selected content is 2D or 3D, its base compatibility, codec, views, and delivered stream. Then identify the exact app, decoder, and output. That turns “Profile 20 fails” into a specific question about reading, view reconstruction, metadata, or presentation.
