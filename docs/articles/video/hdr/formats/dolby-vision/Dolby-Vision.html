    How Dolby Vision Works

    Dolby Vision carries a picture together with information that helps reproduce it on displays with different capabilities. That information can describe the scene and preserve adjustments made while preparing the release.

    A useful way to follow the process is:

    Stage What happens
    Grading The finished HDR appearance is established
    Analysis and optional trims Picture characteristics are measured and mapped results can be adjusted
    Encoding Video and Dolby Vision metadata are packaged for distribution
    Playback A compatible processing path uses the signal and metadata for the target display

    The analysis need not involve a colorist manually adjusting every frame. Dolby describes both shot-based analysis, with optional creative trims, and automatic frame-based analysis for appropriate workflows.

    Dolby Vision is not one interchangeable file format. Its profiles define different ways of delivering the picture. Some have an HDR10 or HLG-compatible base, while others require Dolby Vision-specific interpretation. Some use one video layer; others use two.

    This matters when two Dolby Vision files behave differently in the same Emby app. The label alone leaves out the profile, codec, container, and the capabilities of the complete playback path. Support for one profile is not proof of support for all of them.

    Nor does a Dolby Vision indicator reveal every internal processing step. To understand whether a compatible base picture is being used or additional data is involved, start with fallback compatibility and base and enhancement layers.

    The purpose remains the picture: keep familiar midtones convincing while adapting bright detail and color to the screen available.
