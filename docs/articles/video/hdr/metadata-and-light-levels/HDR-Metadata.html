    HDR Metadata

    HDR metadata is information that accompanies the picture. It can tell a player what the encoded values mean, describe the display used for mastering, or guide adaptation as the scene changes.

    These are different jobs. A useful way to read a media-information report is to separate them:

    Information The question it helps answer
    Transfer characteristics, primaries, matrix How should the pixel values be interpreted?
    Mastering display metadata What color volume was used for grading?
    MaxCLL and MaxFALL What light-level bounds are reported for the content?
    Dynamic metadata What additional information applies to this shot or frame?

    The first row is often called color signaling rather than HDR metadata in a narrower sense. It is still essential to correct playback. A ten-bit stream with the wrong transfer-function tag can be interpreted incorrectly even when its video compression is valid.

    Static metadata applies to the program or sequence; dynamic metadata can change during it. Dynamic does not mean that every pixel carries a separate instruction, nor does a metadata block contain a hidden higher-resolution copy of the movie.

    For Emby troubleshooting, distinguish the source from the delivered stream. During video transcoding, a new picture stream is encoded. Its signaling must describe that output; copying an HDR label onto tone-mapped SDR would not turn it back into HDR.

    Metadata also depends on accurate authoring. A plausible-looking number is not proof that it was measured correctly. MaxCLL and MaxFALL are particularly easy to misread as display specifications, while ST 2086 describes the mastering display instead.
