    FFV1 Lossless Video

    FFV1 is a lossless video coding format. After correct decoding, the stored sample values match the values supplied to its encoder. This makes it useful when preserving video samples is more important than minimizing a delivery file's bitrate.

    FFV1 compresses spatial relationships within pictures without the lossy approximation used in ordinary delivery encodes. Its compression ratio depends on the input: noisy or grainy pictures generally leave less predictable information to compress.

    Conceptual lossless round trip. The comparison applies at the codec's input and output, using the same sample format.

    Define what is being preserved

    Encoding into FFV1 cannot undo an earlier conversion. If a process first reduces bit depth, changes color sampling, or applies a lossy filter, FFV1 preserves the resulting samples. It does not preserve the discarded input information.

    Property What it does and does not establish
    Lossless sample coding Exact reconstruction of the encoder's input samples
    Version 3 slice CRCs, when enabled Detection of damaged slice data, not automatic repair
    A container such as Matroska Packaging for video, audio, and metadata
    A preserved file Still requires storage checks and separate backups

    RFC 9043 describes FFV1 versions 0, 1, and 3. Version 3 includes configuration and slice structures that can support error checking and parallel processing. These features do not guarantee that a consumer app has an appropriate decoder.

    For Emby, an FFV1 preservation file may serve as a source for a separate playback version, provided the server can decode it. Direct decoding in the app and the bitrate needed for delivery remain independent questions. Keep the preservation copy when creating a lossy derivative: that derivative no longer carries the same exact sample guarantee.
