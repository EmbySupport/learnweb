    Video Rotation Metadata

    A phone can record a portrait clip while storing each frame in a landscape grid. Rotation metadata tells the player how to orient that grid for display, so the stored width and height need not match the picture you see.

    QuickTime and related media workflows use display transformation matrices, which can describe rotation as well as other transformations. Media inspectors may present the rotation as a simple angle even when it is represented by a matrix in the file.

    Square-pixel example Stored dimensions Presented dimensions
    No quarter-turn 1920 × 1080 1920 × 1080
    One quarter-turn 1920 × 1080 1080 × 1920

    The table assumes a pure 90° rotation and no additional scaling or crop.

    Rotating the description or the pictures

    There are two ways to make an upright result. A player can rotate the decoded picture while presenting it, leaving the stored samples unchanged. Alternatively, a conversion can rotate the samples and encode a new stream whose dimensions already match the upright picture.

    When the samples are physically rotated, the old rotation instruction must also be handled correctly. Applying the same instruction again can rotate the result twice. Simply deleting metadata from an untouched sideways recording causes the opposite problem: the player loses the information it needed.

    This matters when the same home video looks upright in one Emby playback route and sideways in another. Check the original file's display transformation and the dimensions of any transcoded output. Direct Play and transcoding put the interpretation and processing at different points in the playback path.

    A correct thumbnail is useful evidence, but it does not prove that every playback component has handled the metadata the same way. Compare the actual video as well as the poster or preview image.
