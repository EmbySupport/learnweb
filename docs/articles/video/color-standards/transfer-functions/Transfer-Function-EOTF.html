    Electro-Optical Transfer Function (EOTF)

    An electro-optical transfer function, or EOTF, answers a practical question: how much light should the screen produce for this signal value?

    A pixel value halfway between black and white does not usually request half the light of white. Video uses nonlinear encoding, so equal steps in the signal do not produce equal steps in emitted light.

    For an idealized SDR display with zero black, 100-nit white, and a 2.4 power response, the relationship is L = 100 × V^2.4. Here V is the normalized signal, and L is luminance in nits for neutral gray.

    Normalized signal V Calculated light output
    0.25 3.6 nits
    0.50 18.9 nits
    0.75 50.1 nits
    1.00 100 nits

    These values are an example of BT.1886's zero-black case, not universal settings for every television. PQ uses a different curve and an absolute light-level scale.

    Why the correct curve matters

    Imagine passing the value 0.50 to two renderers with different assumptions about the EOTF. They can agree on the pixel number and still produce different light. That is why a transfer-function mismatch can make an otherwise intact file look too dark or wrong in contrast.

    The EOTF is also separate from numerical range. A limited-range signal must first be interpreted with the correct black and white code values before applying the transfer function.

    When Emby reports Direct Play, it describes delivery from the server. The player and display still have to interpret the video and render it. For HDR-to-SDR playback, the rendering path may need to recover light values using the source EOTF, adapt them through tone mapping, and encode a suitable output signal. None of that is determined by bitrate alone.
