    Lossless Video Compression

    Lossless video compression allows a decoder to reproduce exactly the picture samples supplied to the encoder. It still saves space by representing repetition, prediction errors, and other patterns more efficiently.

    For example, a sequence of sample values can be represented by a starting value and exact differences:

    Representation Values
    Input samples 40, 42, 43, 43
    Starting sample 40
    Following differences +2, +1, 0
    Reconstructed samples 40, 42, 43, 43

    Original arithmetic example. Compact coding of the differences can save bits, but the saving depends on the data and coding method.

    A real lossless codec uses more elaborate predictors and coding rules. FFV1, for example, is a lossless format documented in RFC 9043 and used for preservation and intermediate workflows.

    Lossless relative to which input?

    The guarantee begins at the encoder's input. If a lossy film is decoded and then encoded losslessly, the new file preserves those already decoded samples. It cannot reconstruct detail discarded by the original lossy encoding.

    Likewise, a workflow can change the samples before the lossless stage: resizing, color conversion, reduced bit depth, or chroma subsampling may already have altered the picture. “Lossless video codec” does not certify every operation that preceded it.

    For an Emby library, lossless masters can be useful when preserving home recordings or avoiding repeated encoding damage during editing. They often need substantially more storage and delivery bandwidth than a viewing copy. Compression savings depend strongly on the picture: noise and fine random texture are difficult to represent compactly without approximation.

    Client support also matters. A format well suited to preservation may need server transcoding for a particular app. Keeping a lossless master and a compatible playback version can serve different purposes without treating the smaller viewing copy as the preservation original.
