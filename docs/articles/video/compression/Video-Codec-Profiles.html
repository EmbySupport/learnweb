    Video Codec Profiles

    A decoder needs to understand every coding operation a stream can ask it to perform. A profile selects a permitted set of those operations and sample formats within a codec.

    This is useful both for designing a decoder and for creating a file for a known playback target. The encoder can restrict its choices to the target's tool set, rather than asking the decoder to handle every feature in the complete standard.

    Selected sample-format permissions

    Profile Sample depth Sampling covered by this row
    H.264 Baseline 8-bit 4:2:0
    H.264 Main 8-bit 4:2:0
    H.264 High 8-bit 4:2:0; monochrome also permitted
    H.264 High 10 Up to 10-bit 4:2:0; monochrome also permitted
    HEVC Main 8-bit 4:2:0
    HEVC Main 10 8-bit or 10-bit 4:2:0

    These rows describe selected format permissions, rather than a complete profile specification. They show why a decoder for an ordinary 8-bit stream may need additional sample-processing capability for a 10-bit stream.

    The tools can differ even at the same depth

    H.264 Baseline, Main, and High can all represent 8-bit 4:2:0 pictures, yet their bitstreams can use different operations.

    Entropy coding: CABAC encodes syntax through context-adaptive binary arithmetic coding. Its decoder follows a probability state and arithmetic decoding process. H.264 Main and High permit it; Baseline uses the permitted non-CABAC coding route. Identical final pixel depth does not make those compressed syntax representations interchangeable.

    Picture prediction: Main and High permit B-slices. The associated reference choices and possible reordering require the relevant prediction and buffering behavior. Baseline's restrictions exclude that B-slice tool set.

    Block transforms: High adds permission for an 8×8 transform tool, while Main's transform set is narrower. The decoder must apply the transform described by the stream to reconstruct its corrections.

    The profile label identifies these restrictions as a package. More tools give an encoder different options for representing the source, but the label itself does not select its quantization strength or measure the finished picture.

    Make a stream conform to another profile

    Suppose a target requires H.264 Baseline, while the source uses High with CABAC and 8×8 transforms. Changing the word “High” in metadata leaves the CABAC-coded syntax and transformed blocks in place. The decoder would still encounter operations excluded from the claimed profile.

    Creating the target requires decoding the source and encoding its pictures using the target's actual permitted tools. The encoder restricts entropy coding, prediction, transforms, and any other relevant choices together.

    A High 10 source converted to an 8-bit target also needs a change of sample representation. That happens in the processing/encoding path, rather than being accomplished by relabeling a 10-bit payload.

    A Main 10 HEVC stream can contain SDR or HDR. HDR interpretation comes from the appropriate transfer/color signaling and content; the profile's depth permission describes the sample/tool set.

    Pair the profile with its resource limits

    “HEVC Main 10, Level 5.1, Main tier” describes three aspects: a permitted tool/sample set, a workload level, and a bitrate/buffering tier. The level and tier need to accompany the profile when establishing a decoder target.

    For an Emby playback route, identifying the source profile and the app's usable decoder makes a profile-related conversion understandable. The target encode supplies a representation that conforms to the chosen tool set; it does not improve the source merely by giving it a different profile name.
