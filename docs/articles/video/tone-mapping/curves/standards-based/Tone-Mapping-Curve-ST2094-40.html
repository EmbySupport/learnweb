    Tone Mapping Curve: ST 2094-40 in libplacebo

    The ST 2094-40 mapping used by libplacebo can take its shape from dynamic metadata. A knee marks a transition, and Bézier control points describe the curved section above it. The mapper can then adapt that shape for a display whose peak differs from the metadata's target.

    This is more flexible than assigning one permanent curve to an entire film.

    libplacebo 7.360.1 fallback, 1,000 → 100 nits, zero black levels, default constants, no scene average and no metadata curve anchors. Real metadata can produce a different curve.

    What happens without the metadata?

    The graph deliberately shows that case. libplacebo constructs a fallback curve from its brightness-matching rules instead of requiring a complete metadata-defined Bézier curve.

    The presence of a setting called ST 2094-40 therefore does not prove that a particular film's HDR10+ metadata reached the mapper or was used. It could be operating through this fallback.

    Available information Consequence
    Curve anchors and target information A content-provided curve can be adapted
    Different destination peak The original curve may need adjustment
    Missing curve metadata The implementation uses a generated fallback

    For an Emby playback investigation, the important distinction is between the selected mapping method and the information supplied to it. A remux, transcode, decoder, or renderer boundary can be relevant to the second question; the option name answers only the first.

    Like the other curve plots, this one isolates brightness. It does not demonstrate complete color rendering or certify a playback device's HDR10+ support. Looking at the actual metadata path is more informative than expecting every ST 2094-40 result to resemble one sample graph.
