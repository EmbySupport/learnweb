    Tone Mapping Curve: Gamma

    A gamma tone mapper reshapes brightness with a power function. Compared with uniform scaling, this can give lower values more room while still bringing the source peak down to the output limit.

    FFmpeg 8.1 CPU tone mapper, gamma parameter 1.8, source peak 8 and output white 1. Axes are relative linear light for neutral gray; the very dark region uses FFmpeg's linear extension.

    For most of this example, the operation is output = (input / 8)^(1 / 1.8). An input of 4 becomes about 0.68, rather than the 0.5 produced by dividing everything by eight. That raises the mapped brightness of this value without increasing the output ceiling.

    The near-black detail matters

    Applying a power function all the way to zero can give the darkest values a very steep response. FFmpeg switches to a small linear section below an input of 0.05. The graph represents that implementation detail as well as the main power curve.

    Other implementations use the name differently. libplacebo's gamma mapper retains an unchanged section below a knee, then fits a power curve above it. Its knee parameter is not interchangeable with FFmpeg's gamma parameter.

    Neither setting is simply the display gamma. One is a brightness remapping choice; the other describes a signal/display relationship.

    For Emby users reading logs or comparing images, the useful question is therefore which implementation and parameters are involved. A bare label of Gamma is insufficient to reproduce a result. Pay particular attention to shadow separation as well as overall brightness: lifting a dark region does not guarantee that it gains useful detail.
