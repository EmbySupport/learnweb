    CUDA Tone Mapping

    CUDA tone mapping means that an application runs its tone-mapping calculations on an NVIDIA GPU through CUDA. The application supplies a program, called a kernel, that processes many pixels in parallel.

    CUDA does not prescribe the curve, source-peak estimate, or color handling. Those come from the implementation. Two CUDA tone mappers can therefore produce different pictures, just as a CPU and GPU implementation can aim to produce the same one.

    CUDA, NVDEC, and NVENC do different jobs

    Name Job in a possible video-processing path
    NVDEC Decode compressed video into frames
    CUDA kernel Perform programmable calculations on those frames, such as tone mapping
    NVENC Encode processed frames into a compressed video stream

    NVIDIA documents the video decoder and encoder as hardware engines separate from CUDA cores. Consequently, selecting an NVIDIA decoder or encoder does not by itself prove that tone mapping also runs through CUDA.

    The useful opportunity is keeping decoded frames accessible to subsequent GPU processing. NVIDIA's NVDEC guide describes decoding into video memory and then processing those frames with CUDA. Avoiding an unnecessary trip through system memory can matter as much as accelerating the curve calculation.

    For Emby, inspect the actual processing stages when comparing hardware activity. An encoder can be busy while the tone-mapping work runs somewhere else; a single overall GPU percentage can hide that distinction. A supported codec in NVDEC or NVENC also says nothing by itself about the pixel formats accepted by a particular tone-mapping filter.

    There is no generic CUDA switch that adds this path to every application. The application must include a compatible implementation, and the installed driver and device must satisfy its requirements. The hardware-acceleration documentation describes Emby's platform options; a CUDA-capable graphics card alone is not evidence that every Emby tone-mapping route uses CUDA.
