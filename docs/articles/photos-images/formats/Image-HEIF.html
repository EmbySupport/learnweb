    HEIF and HEIC images

    HEIF is an image-container framework with item relationships and presentation properties; HEIC commonly identifies HEVC-based usage rather than a separate universal image codec.

    HEIF, the High Efficiency Image File Format, describes image-file organization. It is a container framework rather than one compression algorithm. HEIC commonly refers to HEVC-based HEIF usage.

    ISO/IEC 23008-12:2025 is the image-file-format edition linked here. A concrete file's brands, coding and item properties determine what a reader needs.

    The file can describe relationships between images

    An item-oriented resource can designate a principal image and relate other items to it, such as a thumbnail or an auxiliary image. Properties and references help the reader interpret which items form the intended presentation.

    A thumbnail's small dimensions do not make it the authoritative master. An auxiliary image may have another purpose, such as coverage or additional interpretation; it should not automatically appear as a second ordinary photograph.

    The container also supports defined derived-image arrangements. Recovering the principal presentation can therefore involve relationships and transformations as well as one coded payload.

    Codec and presentation requirements meet at the reader

    Requirement What it answers
    Container parsing Which image and associated items belong to the presentation?
    Picture decoding How are the coded samples recovered?
    Property interpretation Which dimensions, transforms and colour description apply?
    Output preparation What representation reaches the app/display?

    A device's HEVC video engine answers only part of picture decoding. It does not establish that an app's photo reader understands all item relationships, metadata or rendering properties.

    AVIF uses an AV1-based image format within related file-format architecture. Changing a filename from HEIC to AVIF does not replace its coded image data.

    In an Emby library, compare the source image with the particular generated or delivered resource. That comparison identifies whether the chosen path retained the intended main picture, rather than inferring full-container preservation from one successful preview.

    An export chooses what to retain

    A conversion to a single ordinary JPEG can create a useful shareable photo while retaining less of a multi-item source. It must decide which presentation to render, how to handle orientation, whether to preserve metadata and how to represent colour/HDR.
