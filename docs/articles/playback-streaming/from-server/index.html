    Overview: From server to player

    Server-to-player delivery selects a media source and a representation compatible with the requested playback path.

    What is being sent, and which parts of the source are being changed? Compatibility and media-source selection establish the options, while Emby's playback modes describe the resulting route. Remuxing, stream copying and track selection give that route more precise meaning than a general statement that the server is streaming a file.

    • How a media server delivers playback
      Media-server playback combines a session decision about sources and tracks with a media-delivery path that may preserve or convert the selected streams.

    • Playback compatibility
      Playback compatibility relates the source representation to the capabilities of the receiving app and its environment.

    • Emby playback modes
      Emby playback modes describe different combinations of source delivery, repackaging and media conversion.

    • Remuxing
      Remuxing places existing encoded streams into another container or delivery package without re-encoding those streams.

    • Stream copying
      Stream copying passes selected encoded stream data to an output path without decoding and re-encoding its pictures or samples.

    • Media source selection
      Media source selection chooses a playable representation by evaluating edition identity, source properties, client conditions and session preferences.

    • Track selection
      Track selection chooses the actual audio and subtitle content for a source, affecting both user presentation and the media processing required by the playback path.
